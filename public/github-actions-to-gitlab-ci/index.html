    What this converter does
    
    
    Paste a GitHub Actions workflow and you get a .gitlab-ci.yml plus a list of everything that did not map cleanly. It is the same idea as the other converters on this site, run the other way: for teams moving from GitHub to GitLab (gitlab.com or self-managed), or keeping both. Conversion runs entirely in your browser; nothing is uploaded.
    
    
    The output is a starting point, not a finished migration. Marketplace actions become the shell commands or GitLab keywords that replace them; anything without a clean equivalent becomes a TODO step that fails loudly, and the notes list the CI/CD variables you need to create.

    Things to check by hand
    
    
      
      
    • The image. GitHub's ubuntu-latest has hundreds of tools preinstalled; ubuntu:24.04 has almost none. Expect to add apt-get install lines, or pick a language image.
      • 
      
    • Merge request pipelines. pull_request becomes merge_request_event; the duplicate-pipeline guard is included when the workflow also ran on push.
      • 
      
    • Outputs between jobs travel as dotenv artifacts. The producing job must write NAME=value lines to build.env; the converter does that for $GITHUB_OUTPUT writes.
      • 
      
    • Windows and macOS. gitlab.com SaaS runner tags are emitted; self-managed GitLab needs runners with those tags, and Windows jobs run PowerShell.
      • 
    
    

    
    FAQ
    
    
    Is my workflow uploaded anywhere?
    
    
    No. The page is static and the converter runs in your tab. Read actions-gitlab.js on GitHub.
    
    
    Can I run it on every workflow in a repository?
    
    
    Yes: npx jenkins-to-actions convert .github/workflows/ci.yml --to gitlab prints the .gitlab-ci.yml; convert each workflow and combine them with include: local:.
    
    
    Why is the output valid but not identical in behaviour?
    
    
    The two systems differ in places that no converter can paper over: caches must live inside the project directory, services are reached by alias rather than localhost, and matrix rows cannot be extended. Each of those is called out in the notes with the fix.
    

    
    Going the other way?
    
    
    Every other page on this site converts to GitHub Actions: Jenkinsfile, GitLab CI, Azure Pipelines, CircleCI, Bitbucket Pipelines and Travis CI.
    
    
    Migrating a whole organisation?
    
    
    The same converters ship as a command-line audit. Point it at a GitHub organisation, a GitLab group, an Azure DevOps organisation, a Bitbucket workspace or a Jenkins server and it inventories every CI configuration it finds, converts what it can, estimates the effort per repository and lists the secrets to create. With --open-prs it opens a pull request in each GitHub repository with the workflow and the notes. Nothing is sent anywhere except the platform you point it at.
    
    
    GITHUB_TOKEN=… npx jenkins-to-actions audit --github-org acme          # report + workflows
GITHUB_TOKEN=… npx jenkins-to-actions audit --github-org acme --open-prs   # one PR per repository
GITLAB_TOKEN=… npx jenkins-to-actions audit --gitlab-group acme/platform
AZURE_DEVOPS_TOKEN=… npx jenkins-to-actions audit --azure-org acme
npx jenkins-to-actions audit --bitbucket-workspace acme --user me --token APP_PASSWORD
npx jenkins-to-actions audit --url https://jenkins.example.com --user me --token APITOKEN
